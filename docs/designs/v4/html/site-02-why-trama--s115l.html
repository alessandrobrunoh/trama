WHY TRAMA
Tasks describe problems.
Agents work directly from Tasks.
Trama keeps one problem per Task, without forcing a session that spans several Tasks into a second project-management object.
THE PROBLEM
Issue trackers assume one ticket is one piece of work. It rarely is anymore.
Five bug reports share one root cause. One fix spans three repositories. Two developers and an agent work in the same context. Work with coding agents needs:
01
Granular Tasks that can be worked on together without duplicating their status.
02
A coding agent that does a large part of the work, and delegates to subagents.
03
Changes tied to a repository and a project, so the reviewer sees what was produced.
04
The why behind a choice, which today lives in a chat thread nobody can find in a month.
“A Task is the unit of work. A session can work across Tasks without a second status to maintain.”
FROM THE TRAMA README
Six things your issue tracker doesn't do.
Everything you expect is still here: statuses, priorities, estimates, views, a timeline and a command palette.
01
Tasks are the unit of work
Each task tracks one piece of work, with its own status, estimate, Delta thread and pull requests.
Elsewhere: tickets overloaded with requests, plans and discussion.
02
Decisions that outlive the chat
Every Delta thread syncs a record: summary, decisions, events, files. Six months later, the why is one click away.
Elsewhere: buried in comments or a wiki page nobody finds.
03
Artifacts with traceability
Pull requests and builds link to the task they address, with CI and review state.
Elsewhere: PR links scattered across tickets.
04
Facts, not fake progress
Burn-up from tasks done, PRs merged and time tracked, not from how long a card sat in a column.
Elsewhere: story points and manual status updates.
05
Contributors, not just assignees
People and agents both work on tasks. Accountability stays with a human.
Elsewhere: one assignee per ticket, human or bot.
06
An inbox for what needs you
Blocked agents, reviews and stale records land in one place, so humans step in where it matters.
Elsewhere: a firehose of notifications for every field change.
