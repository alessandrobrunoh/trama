# Code of Conduct

## Our commitment

Trama is a source-available project built through technical discussion, experimentation, and collaboration.

We want participation in the project to be welcoming, constructive, and safe for contributors regardless of experience level, background, identity, or role.

Everyone participating in Trama is expected to treat others with respect.

## Expected behavior

Examples of behavior that contributes to a healthy community include:

- being respectful and considerate;
- giving technical feedback about ideas and code rather than attacking people;
- explaining disagreement with useful reasoning;
- being open to changing your mind;
- assuming good faith while still addressing harmful behavior;
- helping less experienced contributors understand project conventions;
- respecting different communication styles and levels of English proficiency;
- giving credit for ideas and contributions;
- respecting privacy and confidential information;
- accepting maintainer decisions even when you disagree, while remaining free to discuss them constructively.

Strong technical disagreement is welcome.

Personal hostility is not.

## Unacceptable behavior

Examples of unacceptable behavior include:

- harassment or intimidation;
- discrimination or derogatory comments;
- personal insults;
- threats of violence;
- sexual harassment or unwanted sexual attention;
- deliberate misgendering or identity-based attacks;
- sustained trolling or disruption;
- publishing another person's private information without permission;
- impersonating another contributor;
- knowingly making false accusations;
- repeatedly derailing technical discussions after being asked to stop;
- using project communication channels primarily to provoke or target other people.

## Technical disagreement

Trama is an experimental project. Architecture and product decisions will change.

Contributors are encouraged to challenge ideas.

Good disagreement looks like:

> I think this makes `Execution` too provider-specific because the domain now depends on Delta's current API. Could we keep that inside the adapter?

Unhelpful disagreement looks like:

> This is stupid. Whoever designed this has no idea what they are doing.

Critique the implementation, assumptions, trade-offs, and reasoning — not the person.

## Maintainer responsibilities

Project maintainers are responsible for clarifying and enforcing these standards.

Maintainers may:

- edit or remove inappropriate comments;
- close or lock discussions;
- reject contributions;
- issue warnings;
- temporarily restrict participation;
- permanently ban participants in serious or repeated cases.

Enforcement decisions should be proportionate to the behavior and its impact on the community.

## Reporting conduct issues

If you experience or witness behavior that violates this Code of Conduct, report it privately to the project maintainers.

Do not create a public issue containing sensitive personal information.

If an incident involves a maintainer, contributors should use an alternative private contact method associated with the repository where possible.

Reports should contain enough context for maintainers to understand what happened, but should avoid unnecessary disclosure of private information.

## Privacy

Maintainers should handle conduct reports as privately as reasonably possible.

Information may be shared only when needed to investigate, protect participants, comply with legal obligations, or enforce project rules.

## Scope

This Code of Conduct applies to project spaces including:

- GitHub Issues;
- Pull Requests;
- Discussions;
- code reviews;
- community chat spaces operated by the project;
- project events;
- other public spaces where someone is representing Trama.

## Enforcement principles

Depending on severity and history, maintainers may use responses including:

### Correction

A private or public explanation of why behavior was inappropriate, with a request to correct it.

### Warning

A formal warning that continued behavior may result in restrictions.

### Temporary restriction

Temporary removal from project discussions or contribution channels.

### Permanent ban

Permanent removal from project spaces for serious abuse or repeated violations.

Severe threats, targeted harassment, or deliberate disclosure of private information may result in immediate removal.

## Good-faith moderation

This Code of Conduct is intended to protect constructive collaboration, not suppress ordinary disagreement.

Moderation should not be used to punish someone merely for:

- disagreeing with a maintainer;
- criticizing a technical decision;
- proposing a competing design;
- reporting a legitimate problem;
- asking difficult questions in good faith.

## Changes

This Code of Conduct may evolve as the Trama community grows.

Material changes should be documented in the repository history.

---

By participating in Trama, you agree to follow this Code of Conduct and help keep the project focused on respectful, productive collaboration.
